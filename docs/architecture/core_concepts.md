# Core Concepts & Execution

This document details the critical data structures and execution flows within ICARUS.

## `IcarusModule` Interface

Every security testing engine in ICARUS implements the `IcarusModule` interface.

```java
public interface IcarusModule {
    String getName();
    String getDescription();
    Category getCategory();
    
    // The core execution loop
    void run(HttpRequestResponse baseRequest, ModuleConfig config, FindingRegistry registry);
}
```

By enforcing this contract:
1. The `ScanRunner` can treat all modules uniformly.
2. The UI can dynamically generate settings panels for newly added modules.
3. Thread safety is guaranteed because the module maintains no internal mutable state.

## `ModuleConfig`

The `ModuleConfig` class holds all runtime settings required by a module. This is populated by the `SettingsPanel` in the UI and passed deep into the module via the `ScanRunner`.

It contains data like:
- Global request timeouts.
- Burst sizes for the `RateLimitModule`.
- Enable/Disable toggles for specific fuzzing subsets in the `ParamValidatorModule`.

## `Finding` and `FindingRegistry`

When an `IcarusModule` detects a vulnerability, it instantiates a `Finding` object.

```java
public class Finding {
    private final String title;
    private final String description;
    private final Severity severity;
    private final HttpRequestResponse evidence;
    // ...
}
```

The module then pushes this to the `FindingRegistry`. 
The `FindingRegistry` operates on an Observer pattern. When a new finding is added:
1. It persists the finding to memory.
2. It fires an event to the `IcarusTab` (UI) to update the Results table.
3. It triggers a `ToastNotification` to alert the user.

## The AutoAuth Subsystem

`AutoAuthModule` operates as an interceptor rather than an active scanner. It hooks directly into the Montoya `HttpHandler`.
- When an outgoing request is intercepted, it checks the URL against its Source/Destination map.
- If a match is found, it synchronously fires a background HTTP request to fetch the new token.
- It parses the response, updates the original intercepted request, and allows it to proceed. 

This design allows AutoAuth to intercept traffic generated by *both* manual Repeater testing and automated ICARUS module scanning.
